## 一、核心概念（学到了什么）

### 1. 成本曲线：会话总成本近似轮数平方级

实测（串行任务，10 轮）：
`682 → 1100 → 1257 → 1491 → 1707 → 1910 → 2143 → 2356 → 2607 → 2838`

- 首轮跳变（682→1100）：工具结果里躺着整个文件内容进入历史
- 之后每轮 ~200+ 稳定爬坡：每轮全额重发之前的一切
- 末轮是首轮 5 倍；**单轮成本线性涨，总成本 = 各轮之和 ≈ 平方级**

token 去向：system prompt + 全部历史 + 工具结果 + 思维链（MiMo 的思维链烧输出 token，M1/M4 现象贯穿始终）。

### 2. /compact 的原理与代价

- 原理：让模型把旧历史**摘要成短文本替换掉**——保什么丢什么由压缩指令设计（任务目标/产出/状态保留，过程细节丢弃）
- 实测压缩调用自身输入 2517 token ≈ 曲线末端——**一次性"赎身费"**：花大钱压缩一次，换后续每轮变便宜
- 压缩请求**不带 tools**（摘要不需要工具说明书，还避免模型顺手调工具）
- 压缩后模型记得"产出过哪些文件"，不记得"每个文件的具体内容"——丢失的正是没被点名保留的细节

### 3. 重试与指数退避

- 暂时性错误（429/5xx/网络失败）→ 退避重试；永久性错误（400/401）→ 重试无意义直接抛
- 退避间隔 = 1s→2s→4s 等比 + 500ms 内随机抖动
- **抖动防重试风暴**：服务端抖动时所有客户端同时收到失败，若都按固定间隔重试会形成整齐的重试洪峰把服务器再次打垮；抖动把重试时刻打散成细水
- 实测（打不通的地址）：1114ms → 2214ms → 4388ms，3 次后放弃，共 8.1s

### 4. 工具分级与权限确认（M4 软硬约束合龙的落地）

三档：只读（自动放行）/ 可写（确认）/ 危险（确认+警告）。硬约束全部在程序侧：确认提示由程序弹出；拒绝时把 `{error:"用户拒绝执行该操作..."}` 作为 tool_result 回传，模型会明确向用户汇报"删除被拒绝"。

### 5. Ctrl+C = 暂停 + 存档，而非杀死

Agent 全部状态 = messages 数组 + 磁盘文件。SIGINT 时把 messages 存 JSON，`--resume` 加载后模型根据历史自己接着干——存档到哪，恢复就到哪。M3"强制停三指纹"（无最终回答/半成品/钱已花）的完全解。

### 6. 错误脱敏（M3 踩坑的修复）

工具报错回传前把本机绝对路径替换成 `<本地路径>`——工具结果一字不漏进上下文，环境信息不能跟着进去。

### 实验 1：compact.mjs

- 串行依赖任务（note1→note5 链式追加）撑肥历史，10 轮成本曲线见核心概念 1

## 三、意外发现

1. **重试风暴的通俗理解**（本模块答辩中现场搞懂）：抖动不是防"你一个人重试"，是防"所有人同时重试"——服务端视角下你永远在和并发的人海竞争恢复中的容量
2. **赎身费的直觉**：/compact 不是省钱的魔法，是先花一笔大的（≈历史总量）换后续便宜——长期会话才划算
3. **错误脱敏立竿见影**：M3 踩的"绝对路径泄漏"坑，这次程序自己兜住了

## 四、博客素材点（可直接取用）

- **成本曲线图**：10 轮 682→2838 的实测数据，"Agent 烧钱的真相是平方级"
- **/compact 的赎身费**：压缩那次调用 2517 token 的输入账单——"压缩不免费，但划算"
- **重试风暴比喻**：服务器喘气时被整齐的洪峰再次打倒；抖动 = 大家错峰重试
- **拒绝的礼仪**：用户答 n 之后，模型向用户复述"删除被拒绝"——硬约束不改模型的体面

## 五、检验问答（费曼自测，2026-09-10 通过）

**Q1 成本曲线长什么样？**
> 答：总体累加，首轮到二轮跳变最大（工具结果进历史），之后每轮 200+ 稳定涨，末轮约为首轮 5 倍。
> 补全：单轮线性、总成本平方级；输入大头是反复重发的历史。

**Q2 /compact 的代价？**
> 答：压缩调用自身输入 2517 ≈ 曲线末端，约等于把历史重付一遍。

**Q3 压缩后丢的是什么？**
> 答：记得产出的文件名，不记得具体内容但记得大概；丢的是具体要点展开下的细节信息。
> 补全：丢什么保什么由压缩指令设计决定——细节重要就要在指令里点名保留。

**Q4 确认弹窗是谁的行为？拒绝后模型怎么反应？**
> 答：程序客户端弹的；模型先总结已完成的部分，再明确说删除动作被用户拒绝。

**Q5 退避间隔的数学关系？抖动防什么？**
> 答：等比数列（1s→2s→4s）；抖动防止同时调用。
> 补全（答辩中追问搞懂）：防的是**重试风暴**——所有客户端在服务端抖动后同时重试会形成同步洪峰；哪怕单客户端串行，也在和其他所有用户的并发竞争。

**Q6 续跑靠什么？**
> 答：靠 Ctrl+C 那一刻本地保存的存档 JSON（messages 数组）；存档时干到哪，恢复就到哪。
